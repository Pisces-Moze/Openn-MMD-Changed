# Open MMD In Changed：附属模组开发与模型接入指南

本文针对本项目当前版本编写：Minecraft 1.20.1、Forge 47.4.0、Changed 0.15.7，以及已经嵌入工程的 MC-MMD-rust 渲染运行时。

本文不是普通 Forge 实体教程。这里创建的实体同时具备以下两套行为：

- 服务端玩法、AI、攻击转化、渐变兽化、死亡与属性由 Changed 负责；
- 完成兽化后的实体和玩家外观由 PMX/PMD、VMD 与内嵌 MMD 运行时负责；
- 模型与动画写死在模组 JAR 中，不提供玩家模型选择；
- 启动客户端时，JAR 内资源会覆盖安装到专用缓存目录。

## 1. 当前工程中的完整数据流

以现有 `openmmdchanged:mmd_latex` 为例：

```text
MmdLatexEntity
  └─ ChangedEntity：AI、攻击、Transfur、属性、碰撞箱

ModTransfurVariants.MMD_LATEX
  └─ 玩家 Transfur 后使用的 Changed 形态定义

MmdLatexRenderer
  ├─ 渐变兽化尚未结束：ChangedMmdBridgeModel（Changed 原版渐变动画）
  └─ 渐变完成：MmdSkinRenderer（PMX/PMD + VMD + MMD 物理）

MmdAssetInstaller
  └─ 将 JAR 内 mmd/mmd_latex 复制到固定运行目录
```

注册 ID、模型目录和资源目录必须保持一一对应：

| 用途 | 当前值 |
|---|---|
| 实体 ID | `openmmdchanged:mmd_latex` |
| TransfurVariant ID | `openmmdchanged:mmd_latex` |
| 刷怪蛋 ID | `openmmdchanged:mmd_latex_spawn_egg` |
| JAR 资源目录 | `assets/openmmdchanged/mmd/mmd_latex/` |
| 固定模型文件夹名 | `openmmdchanged.mmd_latex` |
| 游戏运行缓存 | `.minecraft/3d-skin/EntityPlayer/openmmdchanged.mmd_latex/` |

不要直接编辑运行缓存。它会在每次客户端启动时被模组资源覆盖。

假设要添加名为 `cyan_fox` 的新胶兽：


## 3. 模型格式转换：FBX/Unity/VRChat 到 PMX

### 3.1 先保护原始资源

不得直接修改 Unity 原项目中的 FBX、Prefab、PSD、材质或贴图。推荐流程：

1. 将需要转换的 FBX、贴图和必要的材质参考复制到独立工作目录；
2. 保留原文件名与 Unity 材质槽位截图；
3. 为每次导出保留日期备份，例如 `cyan_fox_before_uv_fix.pmx`；
4. 所有合并贴图、发光遮罩和眼睛修复图都输出为新 PNG。

Prefab 不是模型交换格式。应先在 Unity 中确认 Prefab 实际引用的 FBX、SkinnedMeshRenderer、材质与贴图，然后复制这些源资源进行转换。

### 3.2 Blender 与 mmd_tools 基本流程

1. 在 Blender 中启用 `mmd_tools`。
2. 使用“文件 → 导入 → FBX”导入复制出来的 FBX。
3. 检查模型朝向：Minecraft/MMD 中角色应直立，脚底位于原点附近，正面方向保持一致。
4. 检查缩放。不要只靠 PMX 导出时的倍率补偿；先在 Blender 中应用旋转和缩放：

   ```text
   Ctrl+A → Rotation & Scale
   ```

5. 检查网格是否仍绑定到正确的 Armature；不要误删蒙皮权重。
6. 清理重复顶点、反向法线和孤立面，但不要破坏表情网格、眼片、头发卡片或透明材质。
7. 使用 mmd_tools 创建/转换 MMD Model，并将原骨骼映射到 MMD 骨骼。
8. 设置材质名称、纹理路径、透明度、双面显示和边缘参数。
9. 配置必要的刚体、Joint 和裙摆/头发/尾巴物理。
10. 导出为 PMX。PMD 也受支持，但新模型优先 PMX。

### 3.3 推荐的骨骼

动作驱动至少需要可靠映射以下身体骨骼；名称可以是日文 MMD 名或运行时已支持的同义名：

```text
全ての親 / Root
センター / Center
上半身 / UpperBody
上半身2 / UpperBody2
首 / Neck
頭 / Head
左肩、左腕、左ひじ、左手首
右肩、右腕、右ひじ、右手首
下半身 / LowerBody
左足、左ひざ、左足首、左つま先
右足、右ひざ、右足首、右つま先
左足ＩＫ、右足ＩＫ（动作使用 IK 时）
```

头上的角、耳朵、头饰和发饰必须权重绑定到 `Head` 或其子骨骼。尾巴必须建立在骨盆/下半身之后的独立骨骼链上。否则会出现“角跟着身体而不跟头”一类问题。

### 3.4 腿不动时的检查顺序

1. 确认 VMD 中确实存在左右足、膝、足首或足 IK 关键帧；
2. 确认 PMX 骨骼名称与 VMD 名称一致；
3. 确认腿部顶点权重不是错误绑定到下半身或 Center；
4. 确认 IK 链目标和膝关节方向正确；
5. 在 Blender/MMD 预览中播放同一 VMD；
6. 只有上述均正确后，才检查 Java/Rust 动画状态切换。

### 3.5 眼睛、PSD 和 lilToon 材质

Unity 的 lilToon 可以同时组合 Base Color、遮罩、Emission、透明度、裁切和表情切换，而 PMX 的普通材质不能自动复现 Shader Graph。必须把最终显示信息整理成可直接采样的 PNG。

推荐文件约定（文件名区分大小写）：

```text
Body.png       基础身体贴图，不能因发光处理改变基础蓝绿色
Body_eye.png   为眼睛/眼线材质准备的合成贴图
Body_emission.png   Body 材质的独立发光图
hair.png
hair_emission.png   hair 材质的独立发光图
tail.png
tail_emission.png   tail 材质的独立发光图
```

当前运行时的贴图选择规则：

- 面部材质优先使用 `原贴图名_eye.png`；
- 未提供 lilToon 配置的模型默认完全不发光；仅放置 `_emi.png` 不会自动启用；
- 必须由 `useEmission: true`、`emissionTexture` 和 `emissionLayers` 显式声明发光；
- 眼睛 PMX UV 必须实际落在 `Body_eye.png` 的虹膜和眼白区域。

#### 发光图层资源规范（新模型必须遵守）

发光必须与 Base Color 单独分离，禁止把主贴图本身、整张 PSD 合成结果或“所有青色
像素”直接作为正式发光层。否则会导致身体底色变亮、尾巴整体发光，或在不同光影包
下产生大面积黑块。规范如下：

1. 每个 PMX 材质至少对应一张独立 RGBA PNG，命名为
   `<PMX材质名>_emission.png`，例如 `Body_emission.png`；名称必须与
   `liltoon_materials.json` 和 `assets.list` 完全一致。
2. 发光 PNG 必须和该材质的 Base Color 同尺寸、同 UV 方向、同画布原点；推荐
   2048×2048 RGBA、非索引色 PNG。不得裁剪到可见像素边界，也不得翻转 Y 轴。
3. 不发光区域必须为完全透明 `RGBA(0,0,0,0)`；发光区域保留 PSD 中的原颜色和
   Alpha。透明像素的 RGB 也应清零，避免缩放和纹理过滤产生彩边。
4. PSD 内推荐建立 `EMISSION` 图层组，内部使用
   `EMI_01_eyes`、`EMI_02_markings`、`EMI_03_claws` 等稳定且唯一的名字。
   换色顶层组存在时，路径写成 `<换色组>/EMISSION/<语义层>`。不要依赖默认的
   “图层 2”等名字；无法重命名第三方源文件时，必须在项目文档中记录完整层路径。
5. 一个材质的多个发光源通常合成为一张 `<材质>_emission.png`。需要分别控制
   强度时，命名为 `<材质>_emission_<用途>.png`，例如
   `Body_emission_eyes.png`，并在 `emissionLayers` 中逐项注册。
6. 主贴图只负责基础颜色，发光图只负责附加光。禁止把发光结果烘焙回主贴图，禁止
   用 `baseLightFloor` 或 `unlitStrength` 冒充发光。
7. `maskMode: texture` 是正式资产的默认模式。`cyan`、`color` 和 `$base` 颜色筛选
   只允许作为没有 PSD/绘图源文件时的迁移后备，并应在发布前替换为独立贴图。
8. 默认值永远是“不发光”。只有同时满足 `useEmission: true`、至少一个明确的
   `emissionLayers` 项，并为兼容两套渲染后端填写同一张合成图的
   `emissionTexture`，材质才允许发光。文件名、颜色或 `_emi` 后缀不能触发发光。

可使用只读提取工具从 PSD 的指定图层或图层组生成完整 UV 画布：

```powershell
python tools/extract_psd_emission_layers.py `
  --psd "D:\Avatar\Body.psd" `
  --output "src\main\resources\assets\<modid>\mmd\<model>\Body_emission.png" `
  --layer "Variant/EMISSION/EMI_01_eyes" `
  --layer "Variant/EMISSION/EMI_02_markings"
```

工具需要 Pillow 与 `psd-tools`，只读取源 PSD，只写 `--output`。重复 `--layer` 会按
PSD 前后顺序合并，图层组会连同其内部混合和 Alpha 一起合成。已有输出默认拒绝
覆盖；确认后才可加 `--force`。

本项目当前模型的发光来源明确记录为：

- `Body.psd`：`サメトラ/图层 5`、`サメトラ/图层 6`、`サメトラ/爪`、
  `サメトラ/肉球`、`サメトラ/目/瞳`、`サメトラ/目/黒/瞳孔`；
- `tail.psd`：`サメトラ/图层 2`；
- `hair.psd`：`サメトラ/挑染`。

这些路径只是本模型的来源清单，不应硬编码进渲染器。其他开发者必须为自己的模型
填写自己的图层路径并生成独立贴图。

VRChat 手势切换眼睛通常对应 BlendShape/Morph、UV 偏移或材质切换。导出 PMX 时应将需要的表情做成 PMX Morph，并确保每个表情仍使用有效 UV。不能指望 lilToon 的 Unity 参数被 PMX 自动读取。

### 3.6 透明头发和衣服

透明材质建议：

- 贴图使用带 Alpha 的 PNG；
- 在 PMX 材质中启用正确透明度；
- 将不透明身体材质排在前面，将头发卡片、眼片、薄纱等透明材质排在后面；
- 避免多个几乎共面的透明面，否则容易排序闪烁；
- 不要用灰底贴图冒充透明通道。

### 3.7 模型高度

先测量模型在单位缩放下的游戏高度，再修改 `model.properties`：

```properties
size=1.53
size_in_inventory=1.53
```

- `size`：世界、实体和玩家显示倍率；
- `size_in_inventory`：背包预览倍率；
- 碰撞箱不由 PMX 大小决定，而是在 `EntityType.Builder.sized(width, height)` 中设置。

### 3.8 从 Unity Prefab 导入 lilToon 材质

Prefab 负责提供材质引用关系，网格和骨骼仍需按前文转换为 PMX。导入工具只读
Unity 工程，不会修改 Prefab、FBX、材质、PSD 或贴图：

```powershell
python tools/import_unity_liltoon.py `
  --unity-assets "F:\UnityProject\Assets" `
  --prefab "F:\UnityProject\Assets\Avatar\Avatar.prefab" `
  --material-dir "F:\UnityProject\Assets\Avatar\Materials\CurrentVariant" `
  --material-dir-only `
  --output "src\main\resources\assets\openmmdchanged\mmd\cyan_fox" `
  --force
```

参数说明：

- `--unity-assets`：Unity 工程的 `Assets` 根目录；
- `--prefab`：要解析的 Prefab，必须位于该 `Assets` 内；
- `--material-dir`：限定当前换色/服装使用的材质目录，可重复填写；
- `--material-dir-only`：只导入上述目录，避免把 Prefab 的其他换色一起导入；
- `--output`：附属模组自己的模型资源目录，绝不能填写 Unity 原工程目录；
- `--force`：确认覆盖之前生成的 JSON 和复制品；首次导入可省略。

工具会生成 `liltoon_materials.json`，并复制 Unity 材质明确启用的 Emission 与 Normal 贴图。
所有生成文件都要加入 `assets.list`。Unity 材质名与 PMX 材质名不一致时，在对应
配置的 `aliases` 中加入 PMX 名称。运行时匹配顺序为 PMX 材质名、`aliases`、
基础贴图文件名。

常用材质配置模板：

```json
{
  "Body": {
    "aliases": ["Body_FirstPersonHead", "HeadAccessory_Ears_Body_0"],
    "useShadow": true,
    "baseLightFloor": 0.35,
    "unlitStrength": 0.0,
    "shadowBorder": 0.31,
    "shadowBlur": 0.44,
    "shadowColor": [0.76, 0.75, 0.82, 1.0],
    "useRim": true,
    "rimBorder": 0.60,
    "rimBlur": 0.89,
    "rimFresnelPower": 5.1,
    "rimIntensity": 0.225,
    "rimColor": [0.48, 0.55, 0.66, 0.225],
    "useEmission": true,
    "emissionTexture": "Body_emission.png",
    "emissionStrength": 1.0,
    "emissionLayers": [
      {
        "texture": "Body_emission.png",
        "maskMode": "texture",
        "strength": 1.0,
        "color": [1.0, 1.0, 1.0, 1.0]
      }
    ],
    "cyanEmissionStrength": 0.0,
    "useMatCap": false,
    "matCapStrength": 0.0,
    "normalTexture": "",
    "normalScale": 1.0,
    "cull": "back",
    "renderMode": "opaque",
    "alphaCutoff": 0.5,
    "useOutline": true,
    "outlineWidth": 0.1,
    "outlineColor": [0.20, 0.24, 0.32, 1.0]
  }
}
```

兼容边界：Shadow、Rim、Emission 和基础 Outline 已实现；MatCap 是 Minecraft
视图空间近似；Normal 贴图目前只导入不渲染；复杂透明排序仅部分兼容；
Main2nd/Main3rd、AudioLink、Glitter、Dissolve、各向异性和 Unity 光照探针尚未
实现。完整参数表和发光规则见 `docs/lilToon移植分支说明.md`。

#### lilToon 风格化描边规范

描边使用与 lilToon 相同类别的“反向扩壳”思路：顶点沿模型法线向外扩张，反转三角形
绕序并只绘制背面，从而只在轮廓边缘形成线条。每个材质独立配置：

- `useOutline`：是否参与描边；不需要描边的透明片、眼片和内部结构应设为 `false`；
- `outlineWidth`：沿用 Unity lilToon 的数值尺度，运行时按 `×0.01` 转为模型空间宽度；
- `outlineColor`：RGBA 描边颜色和透明度，不与主贴图 RGB 相乘；
- 主贴图只贡献 Alpha 轮廓。运行时会生成“白色 RGB + 原 Alpha”的临时遮罩，避免
  深色主贴图把描边染黑，也能保留头发卡片等透明边缘。

Minecraft 缓冲通道、CPU/OpenGL 和 GPU 通道都会读取相同的逐材质参数。描边不会在
Iris/Oculus 的阴影投射阶段绘制，因此不会扩大实体阴影或生成远处黑块。面部眼睛、
瞳孔、眉毛和口腔等材质默认排除，避免眼片周围形成黑框。其他模型不要在 Java 中
硬编码材质名；只修改该模型自己的 `liltoon_materials.json`。

发光必须遵守：普通材质随环境变暗；独立发光图使用加法混合；黑色为不发光；
`emissionStrength` 控制手绘发光图；`baseLightFloor` 只保护深色基础色，不能替代
Emission。发光不会照亮周围方块，不要给所有材质批量开启。Unity 引用 PSD、TGA
或 JPG 时，导入器会在输出目录转换为 PNG（需要 Pillow），不会修改 Unity 工程。
没有明确配置的普通模型和普通材质始终保持不发光，即使目录中存在同名 `_emi.png`。

## 4. VMD 动画放置与命名

每个模型目录可带自己的 `anims` 文件夹：

```text
anims/
├── idle.vmd
├── walk.vmd
├── sprint.vmd
├── sneak.vmd
├── die.vmd
├── swim.vmd
├── swingLeft.vmd
└── swingRight.vmd
```

现有项目至少内置 `idle`、`walk`、`sprint`、`sneak` 和 `die`。缺少模型专用动作时，运行时会使用 MC-MMD-rust 默认动画，但骨骼命名仍必须兼容。

如果 VMD 来自另一个模型：

1. 在 Blender 中导入目标 PMX；
2. 导入 VMD；
3. 修正骨骼映射、腿 IK、手臂高度与穿模；
4. 将动作重新烘焙到目标 MMD 骨架；
5. 导出目标模型专用 VMD；
6. 在站立、走路、疾跑、潜行、死亡五种状态逐个测试。

Changed 的渐变兽化动画不需要制作 VMD；渐变阶段继续使用 `ChangedMmdBridgeModel` 和 Changed 原版动画，完成后才切换到 PMX。

### 4.1 耳朵、头发、尾巴和衣摆的通用物理

运行时按以下顺序选择物理方案，开发者不需要为某一个角色修改代码：

1. PMX 存在刚体和 Joint 时，使用标准 MMD/Bullet 物理，这是发布模型的首选；
2. VRM 模型使用自身 SpringBone 数据；
3. PMX 没有任何刚体时，才启用通用弹簧骨链回退；
4. 没有可识别骨链时保持原动画，不对不确定的骨骼强行动力学处理。

在 Blender + mmd_tools 中，头发、长耳、尾巴、衣摆等可动部位应由连续父子骨链
组成。给每节骨骼配置刚体，并用 Joint 连接相邻刚体；根部通常跟随骨骼，后续节
使用物理或“物理 + 骨骼”模式。质量、线性/旋转阻尼、角度限制和碰撞组应从小幅度
开始调整，避免模型生成时爆炸、穿过身体或无限抖动。身体碰撞体放入单独碰撞组，
并用碰撞遮罩排除同一条链相邻节之间不必要的碰撞。

对于只有 VRChat PhysBone 骨链、尚未制作 PMX 刚体的模型，回退系统会按骨骼名
识别 `hair/髪/发/髮`、`tail/尾`、`ear/耳`、`ribbon/リボン`、
`skirt/スカート`、`cape`、`cloth`、`phys`、`spring` 等通用标记，沿连续子骨骼
建立弹簧链。分叉发束应拆成不同根骨并采用清晰编号；不要把身体主骨命名成这些
关键词。回退仅用于让未配置物理的模型可用，不包含 Unity PhysBone 的所有碰撞体、
抓取、拉伸和参数曲线。需要稳定且可控的发布质量时，应将 PhysBone 参数人工映射为
PMX 刚体与 Joint。

测试时至少覆盖：静止、走路、疾跑、急停、跳跃、潜行、乘船、低帧率和多人同屏。
如果性能不足，优先减少骨链节数与碰撞对，而不是关闭全部模型动画。

## 6. 注册 Changed 实体

### 6.1 实体类模板

```java
package com.moze.openmmdchanged.entity;

import net.ltxprogrammer.changed.entity.ChangedEntity;
import net.ltxprogrammer.changed.entity.TransfurMode;
import net.ltxprogrammer.changed.entity.latex.LatexType;
import net.ltxprogrammer.changed.init.ChangedLatexTypes;
import net.minecraft.world.entity.EntityType;
import net.minecraft.world.level.Level;

public final class CyanFoxEntity extends ChangedEntity {
    public CyanFoxEntity(EntityType<? extends CyanFoxEntity> type, Level level) {
        super(type, level);
    }

    @Override
    public TransfurMode getTransfurMode() {
        return TransfurMode.REPLICATION;
    }

    @Override
    public LatexType getLatexType() {
        // NONE：不加入黑胶/白胶阵营；也可以返回 DARK_LATEX 或 WHITE_LATEX。
        return ChangedLatexTypes.NONE.get();
    }
}
```

`ChangedEntity` 已包含 Changed 的近战、追踪和转化行为。除非确实要改变 AI，否则不要重新实现整套攻击逻辑。

### 6.2 “实体类型”实际有三种含义

| 设置 | 作用 | 常用值 |
|---|---|---|
| `MobCategory` | Minecraft 生成分类、刷怪规则 | `MONSTER`、`CREATURE` |
| `LatexType` | Changed 阵营与敌我关系 | `NONE`、`DARK_LATEX`、`WHITE_LATEX` |
| `TransfurMode` | 实体如何转化受害者 | `REPLICATION`、`ABSORPTION`、`NONE` |

主动 Transfur 玩家通常使用：

```text
MobCategory.MONSTER
TransfurMode.REPLICATION
ChangedLatexTypes.NONE/DARK_LATEX/WHITE_LATEX
```

`REPLICATION` 会把实体对应的形态复制给玩家；`ABSORPTION` 是吸收式；`NONE` 不执行 Changed 转化。

### 6.3 EntityType 与属性模板

在 `ModEntities.java` 中：

```java
public static final RegistryObject<EntityType<CyanFoxEntity>> CYAN_FOX = REGISTRY.register(
        "cyan_fox",
        () -> EntityType.Builder.of(CyanFoxEntity::new, MobCategory.MONSTER)
                .clientTrackingRange(10)
                .sized(0.70F, 1.93F)
                .build(OpenMmdChanged.id("cyan_fox").toString()));

public static AttributeSupplier.Builder createCyanFoxAttributes() {
    return ChangedEntity.createLatexAttributes()
            .add(Attributes.MAX_HEALTH, 24.0D)
            .add(Attributes.FOLLOW_RANGE, 40.0D)
            .add(Attributes.MOVEMENT_SPEED, 0.30D)
            .add(Attributes.ATTACK_DAMAGE, 3.0D)
            .add(Attributes.ARMOR, 4.0D);
}
```

在主类的属性事件中：

```java
private static void registerAttributes(EntityAttributeCreationEvent event) {
    event.put(ModEntities.MMD_LATEX.get(), ModEntities.createMmdLatexAttributes().build());
    event.put(ModEntities.CYAN_FOX.get(), ModEntities.createCyanFoxAttributes().build());
}
```

`sized(0.70F, 1.93F)` 是碰撞箱宽高，不是模型缩放。模型高度变化后，要分别检查站立、潜行、游泳和死亡姿势的碰撞箱。

## 7. 注册 TransfurVariant

在 `ModTransfurVariants.java` 中：

```java
public static final RegistryObject<TransfurVariant<CyanFoxEntity>> CYAN_FOX = REGISTRY.register(
        "cyan_fox",
```

必须继续在主类构造器中注册：


常见 Builder 设置：

- `.replicating()`：复制式转化；
- `.absorbing()`：吸收式转化；
- `.nightVision()`：夜视；

- `.disableItems()`：禁用物品；
- `.holdItemsInMouth()`：口持物品。

## 8. 注册实体渲染器

### 8.1 固定模型文件夹

在安装器中为每个形态定义唯一常量：

```java
public static final String CYAN_FOX_FOLDER = "openmmdchanged.cyan_fox";
```

### 8.2 渲染器模板

建议复制现有 `MmdLatexRenderer`，只替换泛型、BridgeModel 和固定模型文件夹：

```java
public final class CyanFoxRenderer
        extends AdvancedHumanoidRenderer<CyanFoxEntity, CyanFoxBridgeModel> {
    private final MmdSkinRenderer<CyanFoxEntity> mmdRenderer;

    public CyanFoxRenderer(EntityRendererProvider.Context context) {
        super(context,
                new CyanFoxBridgeModel(context.bakeLayer(CyanFoxBridgeModel.LAYER)),
                ArmorHumanModel.MODEL_SET,
                0.5F);
        mmdRenderer = new MmdSkinRenderer<>(context, MmdAssetInstaller.CYAN_FOX_FOLDER);
    }

    @Override
    public void render(CyanFoxEntity entity, float yaw, float partialTick,
                       PoseStack poseStack, MultiBufferSource buffers, int packedLight) {
        if (isGraduallyTransfurring(entity, partialTick) || !hasBundledModel()) {
            super.render(entity, yaw, partialTick, poseStack, buffers, packedLight);
        } else {
            mmdRenderer.render(entity, yaw, partialTick, poseStack, buffers, packedLight);
        }
    }

    // isGraduallyTransfurring() 与 hasBundledModel() 直接参照 MmdLatexRenderer。
}
```

BridgeModel 仅用于：

- Changed 原版渐变兽化阶段；
- PMX 丢失或加载失败时的安全回退；
- Changed 需要标准头、躯干、手臂和腿部接口时。

它不是最终外观，不需要复刻 PMX 的全部细节。

### 8.3 客户端注册

```java
public static void register(EntityRenderersEvent.RegisterRenderers event) {
    event.registerEntityRenderer(ModEntities.MMD_LATEX.get(), MmdLatexRenderer::new);
    event.registerEntityRenderer(ModEntities.CYAN_FOX.get(), CyanFoxRenderer::new);
}

public static void registerLayers(EntityRenderersEvent.RegisterLayerDefinitions event) {
    event.registerLayerDefinition(ChangedMmdBridgeModel.LAYER, ChangedMmdBridgeModel::createBodyLayer);
    event.registerLayerDefinition(CyanFoxBridgeModel.LAYER, CyanFoxBridgeModel::createBodyLayer);
}
```

实体、属性和 Variant 在服务端也要注册；只有渲染器、LayerDefinition 和 MMD 资源安装属于客户端。

## 10. 添加对应针剂与带转化药的弓箭

### 10.1 不要重复注册新的针剂类

Changed 已提供两个通用物品：

```text
changed:latex_syringe
changed:latex_tipped_arrow
```

具体形态存放在物品 NBT 的 `form` 字段中。因此每个附属形态通常只需要创建对应 `ItemStack`，不需要注册新的 `Item`。

```java
private static ItemStack pureVariantStack(Item item,
                                          RegistryObject<? extends TransfurVariant<?>> variant) {
    return Syringe.setPureVariant(new ItemStack(item), variant.getId());
}

public static ItemStack cyanFoxSyringe() {
    return pureVariantStack(ChangedItems.LATEX_SYRINGE.get(), ModTransfurVariants.CYAN_FOX);
}

public static ItemStack cyanFoxArrow() {
    return pureVariantStack(ChangedItems.LATEX_TIPPED_ARROW.get(), ModTransfurVariants.CYAN_FOX);
}
```

`.setPureVariant()` 会写入安全形态；需要不安全针剂时使用：

```java
Syringe.setUnpureVariant(stack, ModTransfurVariants.CYAN_FOX.getId());
```

### 10.2 加入 Changed 物品分类

Changed 自己的创造栏只自动枚举 `changed` 命名空间的形态，附属命名空间需要主动添加：

```java
private static void addCreativeTabItems(BuildCreativeModeTabContentsEvent event) {
    if (event.getTabKey() == CreativeModeTabs.SPAWN_EGGS) {
        event.accept(ModItems.CYAN_FOX_SPAWN_EGG.get());
    }

    if (event.getTabKey() == ChangedTabs.TAB_CHANGED_ITEMS.getKey()) {
        event.accept(Syringe.setPureVariant(
                new ItemStack(ChangedItems.LATEX_SYRINGE.get()),
                ModTransfurVariants.CYAN_FOX.getId()));
        event.accept(Syringe.setPureVariant(
                new ItemStack(ChangedItems.LATEX_TIPPED_ARROW.get()),
                ModTransfurVariants.CYAN_FOX.getId()));
    }
}
```

针剂使用时直接调用 Changed 的完整注射逻辑；转化箭命中实体后调用 Changed 的渐进转化逻辑。不要额外在箭命中事件中再次执行 Transfur，否则会发生双重进度。

### 10.3 物品名称如何显示

- 刷怪蛋使用本模组语言键：`item.openmmdchanged.cyan_fox_spawn_egg`；
- 针剂本体仍叫 Changed 的“乳胶针剂”；
- 转化箭本体仍叫 Changed 的“乳胶箭/转化箭”；
- 两者 Tooltip 中的具体形态名来自实体语言键：`entity.openmmdchanged.cyan_fox`。

因此必须提供实体翻译，否则针剂和箭会显示未翻译的注册键。

### 10.4 针剂与转化箭贴图怎么处理

推荐方案不为每个形态注册新的针剂和箭，也不复制 Changed 的贴图。以下两个物品本身已经包含模型、贴图、使用动画和命中逻辑：

```text
changed:latex_syringe
changed:latex_tipped_arrow
```

物品 NBT 中的 `form=openmmdchanged:cyan_fox` 决定它对应哪个形态。Changed 客户端会读取该 Variant 的实体类型，再使用实体注册的背景色和高亮色给针剂药液与箭头药剂区域染色。

为了让附属形态稳定获得正确颜色，应在模组公共初始化阶段显式登记：

```java
import net.ltxprogrammer.changed.init.ChangedEntities;

public OpenMmdChanged(FMLJavaModLoadingContext context) {
    IEventBus modBus = context.getModEventBus();
    // 其余注册代码……

    ChangedEntities.registerEntityColor(
            OpenMmdChanged.id("cyan_fox"),
            0x244A52, // 针剂/箭的基础药液色，也建议与刷怪蛋背景色一致
            0x65F4FF  // 高亮色，也建议与刷怪蛋斑点色一致
    );
}
```

因此推荐方案的资源清单中只有刷怪蛋模型 JSON，不需要这些文件：

```text
textures/item/cyan_fox_syringe.png      不需要
textures/item/cyan_fox_arrow.png        不需要
models/item/cyan_fox_syringe.json       不需要
models/item/cyan_fox_arrow.json         不需要
```

针剂与箭仍显示 Changed 的通用物品名，并在 Tooltip 中显示 `entity.openmmdchanged.cyan_fox` 对应的形态名称。

#### 完全自定义针剂/箭贴图（不推荐作为第一版）

如果希望每个形态拥有完全不同的瓶身或箭头图案，必须注册新的 `Item`，仅仅添加 PNG 不会替换带 NBT 的 Changed 通用物品。推荐目录：

```text
└── cyan_fox_arrow.png

src/main/resources/assets/openmmdchanged/models/item/
├── cyan_fox_syringe.json
```

```json

  "textures": {
    "layer0": "openmmdchanged:item/cyan_fox_syringe"
```

除非确实需要改变瓶身轮廓，优先使用 Changed 通用贴图加形态颜色：兼容性最好，也不需要维护重复的物品逻辑。

## 11. 穿盔甲后的模型应该是什么样子

### 11.1 双足人形形态的外观规范

对于当前这种双足人形 PMX：

- 头盔跟随 `Head`，覆盖头顶和后脑，但不要遮住眼睛、耳朵和角；
- 胸甲跟随上半身、左右臂，保持肩部活动空间；
- 护腿跟随骨盆、大腿和小腿；
- 靴子跟随足首和脚部；
- 盔甲网格应比身体表面略大，避免 Z-fighting，但不能整体膨胀到悬空；
- 尾巴、耳朵、角、长发等种族特征应从盔甲外露出；
- 潜行、走路、跑步、游泳和死亡动作中都不能明显穿模。

### 11.2 当前工程的实际限制

渐变兽化和回退阶段使用 `ArmorHumanModel.MODEL_SET`，可以走 Changed 的普通人形盔甲渲染。

完全兽化后，`MmdLatexRenderer` 直接调用 `MmdSkinRenderer`，此阶段不会自动把 Minecraft 的方块式盔甲网格贴合到任意 PMX 身材。仅在构造器里写 `ArmorHumanModel.MODEL_SET`，不能让最终 PMX 自动穿上盔甲。

### 11.3 推荐方案：在 PMX 内预制盔甲网格

这是最适合固定模型的方案：

1. 在 Blender 中复制身体附近的基础网格或重新制作贴合盔甲；
2. 分成四组独立网格/材质；
3. 使用与身体相同的骨骼和权重；
4. 材质名称使用固定前缀：

   ```text
   armor_head_iron
   armor_chest_iron
   armor_legs_iron
   armor_feet_iron
   ```

5. 默认隐藏这些材质；
6. 渲染每帧读取 `EquipmentSlot.HEAD/CHEST/LEGS/FEET`，按实际装备显示对应材质；
7. 为皮革、铁、金、钻石、下界合金以及需要支持的模组盔甲制作材质组。

材料索引可通过 MMD 原生接口的材质名称查询确定。显示切换使用：

```java
long handle = model.modelInstance().getModelHandle();
int materialIndex = MmdSkinApi.findMaterialIndex(handle, "armor_head_iron");
MmdSkinApi.setMaterialVisible(handle, materialIndex, visible);
```

建议把“材质名 → 索引”只在模型加载完成时缓存一次，不要每帧遍历全部材质。

装备槽判断模板：

```java
public static void applyArmorVisibility(Player player, long modelHandle,
                                        IntConsumer show, IntConsumer hide) {
    boolean helmet = !player.getItemBySlot(EquipmentSlot.HEAD).isEmpty();
    boolean chest = !player.getItemBySlot(EquipmentSlot.CHEST).isEmpty();
    boolean legs = !player.getItemBySlot(EquipmentSlot.LEGS).isEmpty();
    boolean feet = !player.getItemBySlot(EquipmentSlot.FEET).isEmpty();

    setGroupVisible(ARMOR_HEAD_INDICES, helmet, show, hide);
    setGroupVisible(ARMOR_CHEST_INDICES, chest, show, hide);
    setGroupVisible(ARMOR_LEGS_INDICES, legs, show, hide);
    setGroupVisible(ARMOR_FEET_INDICES, feet, show, hide);
}

private static void setGroupVisible(int[] indices, boolean visible,
                                    IntConsumer show, IntConsumer hide) {
    for (int index : indices) {
        (visible ? show : hide).accept(index);
    }
}
```

调用示例：

```java
IntConsumer show = index -> MmdSkinApi.setMaterialVisible(modelHandle, index, true);
IntConsumer hide = index -> MmdSkinApi.setMaterialVisible(modelHandle, index, false);
applyArmorVisibility(player, modelHandle, show, hide);
```

上面只展示槽位开关。正式实现还应判断 `ArmorItem.getMaterial()`，选择铁、钻石等对应材质组。

### 11.4 备选方案：渲染 Changed/原版盔甲层

也可以在 MMD 绘制之后额外渲染 `HumanoidArmorLayer`，但它仍使用 Minecraft 人形骨架。只有 PMX 身材、关节位置和原版玩家非常接近时才适合；否则肩膀、膝盖、头部和身体会错位。

对于兽耳、角、尾巴和非标准比例角色，优先使用 PMX 内预制盔甲网格。

四足形态应在 Variant 上调用 `.quadrupedal()` 并制作四足护腿/靴子外观；无腿形态调用 `.noLegs()`，使用 Changed 的上/下腹部盔甲规则。官方 Wiki 说明这两类盔甲由 Changed 单独限制，普通双足盔甲不能直接混用。

## 12. 物品属于哪个分类

推荐分类如下：

| 内容 | 分类 |
|---|---|
| 胶兽刷怪蛋 | 原版 `CreativeModeTabs.SPAWN_EGGS`，可选同时加入 Changed 实体页 |

同一个物品可以出现在多个创造栏，但不要重复注册多个相同 ID 的物品。

## 14. 构建与测试

### 14.1 构建

在项目根目录运行：

```powershell
.\gradlew.bat build --no-daemon
```

输出位于：

```text
build/libs/openmmdchanged-1.0.jar
```

构建任务会同时处理内嵌 Rust MMD 运行时。首次构建耗时明显更长。

### 14.2 最低测试清单

1. 使用刷怪蛋生成实体，不崩溃；
2. 实体主动追踪并攻击玩家；
3. 攻击使用 Changed 原版 Transfur 进度；
4. `/tf @s openmmdchanged:形态ID` 正常；
5. 渐变阶段使用 Changed 原动画；
6. 完成后切换 PMX；
7. 站立、走路、疾跑、潜行、死亡 VMD 正常；
8. 第一人称不显示头部和遮挡相机的头饰；
9. 第三人称和其他玩家视角头部完整；
10. 生存背包预览头部完整、位置正确；
11. 受伤时出现红色 Hurt Overlay；
12. 死亡/复活后 Transfur 状态和玩家模型恢复；
13. 针剂 Tooltip 显示正确形态名并能转化；
14. 转化箭命中后增加正确形态的转化进度；
15. 白天基础色不改变，夜间仅 `emissionTexture` 与显式启用的青色荧光区域保持全亮；
16. 透明头发、衣服、眼片没有明显排序错误；
17. 穿盔甲后各槽位外观与动作正确。

### 14.3 常见故障定位

| 问题 | 优先检查 |
|---|---|
| 模型完全不显示 | `assets.list`、固定文件夹名、PMX 文件名、客户端日志 |
| 贴图紫黑/缺失 | PMX 内相对路径、文件大小写、是否列入 `assets.list` |
| 眼睛全黑 | 眼球最外层 UV、`Body_eye.png`、材质顺序，不要只调亮度 |
| 腿不动 | VMD 腿骨/IK 名称、PMX 权重、IK 链 |
| 角不跟头 | 角/装饰品权重是否绑定 Head 或其子骨骼 |
| 第一人称遮挡 | 第一人称材质隐藏范围、头饰是否归入头部材质/骨骼 |
| 背包预览无头 | 第一人称模式是否在 Inventory 场景前关闭 |
| 夜间不发光 | `useEmission`、`emissionTexture`、PNG 是否在 `assets.list`，蒙版 UV 是否与基础贴图一致 |
| 暗处全身发光 | 不要把 Base Color 当发光图；检查 Emission PNG 的非发光区域是否为黑色/透明 |
| 基础蓝绿色变浅 | 不要把 Emission 烘焙回 `Body.png`，只改显式配置的 `Body_emission.png` |
| 实体不 Transfur | 必须继承 `ChangedEntity`、注册 Variant、模式不能是 `NONE` |
| 针剂变成错误形态 | NBT `form` 必须是 Variant ID，不是实体类名或模型文件夹名 |

## 15. 添加一个新固定形态的最短步骤

1. 备份并复制 FBX/贴图到独立工作目录；
2. 用 Blender + mmd_tools 转为 PMX，修好骨骼、UV、透明度和物理；
3. 制作 `idle/walk/sprint/sneak/die.vmd`；
4. 将模型资源放入新的 `assets/openmmdchanged/mmd/<id>/`；
5. 填写 `assets.list` 与 `model.properties`；
6. 新建继承 `ChangedEntity` 的实体；
7. 注册 `EntityType` 和属性；
8. 注册同 ID 的 `TransfurVariant`；
9. 注册刷怪蛋、语言键和物品模型；
10. 创建 BridgeModel、MMD Renderer 并注册客户端渲染；
11. 在安装器中增加唯一固定模型文件夹；
12. 将对应针剂和转化箭 ItemStack 加入 Changed 物品分类；
13. 构建并按测试清单逐项验证。
