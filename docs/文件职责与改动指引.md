# Open MMD In Changed · 文件职责与改动指引

> 这篇手册回答三个问题：**改哪个文件、它有什么用、具体怎么改**。
> 先看本页定位自己要做的事，再翻 `docs/附属模组开发与模型接入指南.md`（全流程细节）
> 与 `docs/命名与资产规范.md`(命名/贴图/动画规范)。本文只针对**模组自身**的文件
> （`com.moze.openmmdchanged` + 资源）；`com.shiroha.mmdskin` 与 `rust_engine` 是引擎，
> 见第 4 节的边界说明。

---

## 0. 一分钟看懂项目

```
openmmdchanged (模组粘合层, 你改这里)
   ├─ 实体/形态/物品注册   → registry/
   ├─ 实体逻辑(AI继承Changed)→ entity/
   ├─ 客户端渲染编排        → client/render/
   ├─ 资源安装到运行目录     → client/MmdAssetInstaller.java
   └─ 第一人称/手持/世界mixin → mixin/client/

shiroha.mmdskin (渲染引擎, 一般不改)
   └─ PMX/PMD加载·蒙皮·lilToon材质·表达·物理·第一人称相机

rust_engine (核心MMD运行时, 一般不改)
   └─ 模型/动画(VMD/FBX)/物理(Bullet)/IK·蒙皮, 经JNI暴露给Java
```

**三层分工**

| 层 | 职责 | 何时需要改 |
|---|---|---|
| `com.moze.openmmdchanged` | 一个形态对应的实体、形态、物品、渲染编排、资源 | **绝大多数新增/改形态工作都在这一层** |
| `com.shiroha.mmdskin` | PMX 渲染引擎：加载、蒙皮、材质、表达、相机，与 Changed/Minecraft 桥接 | 只有改渲染行为/材质/相机才动 |
| `rust_engine` | MMD 核心：格式解析、动画、物理、IK | 只有改模型/动画/物理内核才动 |

## 1. 每个文件的职责与「改什么」

### 1.1 模组粘合层（`com.moze.openmmdchanged`）

| 文件 | 作用 | 客户端/服务端 | 常见改动场景 |
|---|---|---|---|
| `OpenMmdChanged.java` | 模组入口。注册实体/物品/形态、绑定属性事件、创造栏添加物品、客户端注册渲染器/按键、启动时安装资产、初始化 MMD 客户端与表情轮盘 | BOTH | 新增形态后：加属性注册、加创造栏物品、加客户端初始化逻辑 |
| `entity/MmdLatexEntity.java` | 该形态的实体类，继承 `ChangedEntity`，决定转化模式 | BOTH | 新增形态时复制，改类名/`getTransfurMode`；一般不改 AI（继承了 Changed） |
| `registry/ModEntities.java` | 注册 `EntityType`（实体 ID、分类、碰撞箱尺寸、追踪范围）与属性 | BOTH | 新增形态：注册实体 + 属性 |
| `registry/ModTransfurVariants.java` | 注册 `TransfurVariant`（玩家变身形态，replicating/absorbing、夜视等） | BOTH | 新增形态：注册 Variant，Variant ID 须与实体 ID 相同 |
| `registry/ModItems.java` | 注册刷怪蛋（`ForgeSpawnEggItem`，背景色/斑点色） | BOTH | 新增形态：注册刷怪蛋 |
| `client/MmdAssetInstaller.java` | 客户端启动时把 JAR 里的 `assets/openmmdchanged/mmd/<id>/` 按 `asset.list` 拷贝到 `.minecraft/3d-skin/...` | CLIENT | 新增形态：加固定模型文件夹常量，并把新目录传给安装逻辑 |
| `client/render/ChangedMmdBridgeModel.java` | Changed 渐变兽化阶段用的简易人形模型 | CLIENT | 新增形态：可复制，仅用于渐变/回退/手持 |
| `client/render/MmdLatexRenderer.java` | 最终渲染器：渐变阶段用 Bridge，完成后切 `MmdSkinRenderer`(PMX) | CLIENT | 新增形态：复制，改泛型、Bridge、固定模型文件夹 |
| `client/render/ModEntityRenderers.java` | 注册实体渲染器与 LayerDefinition | CLIENT | 新增形态：注册渲染器 + 层 |
| `mixin/client/CameraMixin.java` | MMD 第一人称视角（用 MMD 眼骨定位相机） | CLIENT | 一般不改；除非调整第一人称相机偏移 |
| `mixin/client/ItemInHandRendererMixin.java` | 调整手持物品绘制以配合 MMD 第一人称 | CLIENT | 一般不改 |
| `mixin/client/LevelRendererMixin.java` | 世界渲染状态在发光/描边通道后恢复（隔离光影包状态） | CLIENT | 一般不改；涉及光影状态隔离 |
| `mixin/LivingEntityMixin.java` | 在原版移动结算后调用水面漂浮控制器 | BOTH | 调整持续跳跃检测或实际水面锁定时 |
| `player/WaterFloatController.java` | 锁定水面高度、清除竖直速度，并在靠近岸边时释放 | BOTH | 调整触发延迟、浸水深度或岸边检测范围 |

### 1.2 资源文件（`src/main/resources`）

| 文件/目录 | 作用 | 改动场景 |
|---|---|---|
| `assets/openmmdchanged/mmd/<id>/` | **模型资产根目录**（pmx、贴图、动画、材质配置、`asset.list`） | 新增/替换形态的主要阵地，见 `docs/命名与资产规范.md` |
| `assets/openmmdchanged/lang/{zh_cn,en_us}.json` | 实体名/刷怪蛋名显示 | 新增形态：加 `entity.` 与 `item.` 两个语言键 |
| `assets/openmmdchanged/models/item/<id>_spawn_egg.json` | 刷怪蛋物品模型（继承原版模板上色） | 新增形态：新建 |
| `data/changed/tags/entity_types/latexes.json` | 把本模组实体加入 Changed 的"胶兽"标签 | 新增形态：把实体 ID 加进该标签（若要有胶兽语义） |
| `META-INF/mods.toml` | 模组元数据：modid、版本、依赖(forge/minecraft/changed) | 更新版本/依赖时 |
| `openmmdchanged.mixins.json` | 声明哪些 mixin 启用（`client.*`） | 新增/删除 mixin 时 |

> `assets/mmdskin/`（默认动画、shader、语言）与 `data/` 一般不动，属引擎自带资源。

## 2. 常见任务 → 具体改这几个文件

### 任务 A：新增一个 MMD 胶兽形态（如 `cyan_fox`）

1. **模型资产**：把 `model.pmx`、贴图、`anims/*.vmd` 放进
   `assets/openmmdchanged/mmd/cyan_fox/`，写 `asset.list`、`model.properties`、可选
   `liltoon_materials.json`、`secondary_motion.json`。
2. **实体**：复制 `entity/MmdLatexEntity.java` → `entity/CyanFoxEntity.java`，改类名。
3. **注册实体**：`registry/ModEntities.java` 加
   `CYAN_FOX` 的 `EntityType`（用 `openmmdchanged:cyan_fox`）与属性。
4. **注册形态**：`registry/ModTransfurVariants.java` 加 `CYAN_FOX`（Variant ID 相同）。
5. **注册刷怪蛋**：`registry/ModItems.java` 加 `CYAN_FOX_SPAWN_EGG`。
6. **注册渲染**：`client/render/` 新建 `CyanFoxBridgeModel`、`CyanFoxRenderer`；
   `ModEntityRenderers.java` 注册两者；`MmdAssetInstaller.java` 加
   `CYAN_FOX_FOLDER="openmmdchanged.cyan_fox"`。
7. **主类**：`OpenMmdChanged.java` 加属性注册、创造栏物品、`ChangedEntities.registerEntityColor`。
8. **资源**：加两个语言键、刷怪蛋模型 JSON、`latexes.json` 标签。
9. **测试**：按 `docs/附属模组开发与模型接入指南.md` §14.2 测试清单逐项验证。

> 每一步的具体模板与代码示例都已在 `docs/附属模组开发与模型接入指南.md`
> §6~§13 给出。命名与贴图规范见 `docs/命名与资产规范.md`。

### 任务 B：替换某个形态的贴图

1. 把新 PNG 放进 `assets/openmmdchanged/mmd/<id>/`，**文件名必须**与 `liltoon_materials.json`
   和 `asset.list` 完全一致。
2. 若换了 PMX 材质名，在 `liltoon_materials.json` 该材质的 `aliases` 里补 PMX 名。
3. 在 `asset.list` 里逐行列出新文件；没有它，模型找不到。
4. 发光贴图必须为 `<材质>_emission.png`（禁止 `_emi`、禁止烘焙回 Base Color）。

### 任务 C：只改渲染表现（贴图色、阴影、描边、发光）

不用动 Java。只改该模型目录下的 `liltoon_materials.json`。逐材质字段含义见
`docs/命名与资产规范.md` §7 与 `docs/lilToon移植分支说明.md`。

### 任务 D：修第一人称视角遮挡

这是渲染引擎行为，一般改 `mixin/client/CameraMixin.java` 或 mmdskin 的第一人称相机/头部隐藏逻辑，
而非模型。必要时在 PMX 里把头部/头饰材质归到 `Head` 骨。

### 任务 E：把默认 A-pose 换成通用人形（VRChat / Mixamo）动作

模型自带待机 `idle.vmd` 只动画上半身+手臂，腿/下半身/手腕留在绑定姿态 → 僵硬 A-pose。
引擎已内置 Mixamo / Unreal Mannequin 人形骨骼 → MMD 骨映射与臂肩重定向，可直接加载人形 FBX
（任意模型通用）。完整导出、命名、放置、`asset.list`、`animations.json` 映射、许可与骨名兼容说明见
[`docs/通用人形动作接入指南.md`](通用人形动作接入指南.md)。

## 4. 引擎边界：什么时候不该动 `mmdskin` / `rust_engine`

**不要**为了"让某个模型的材质发光/加描边/换贴图"去改 `mmdskin` 或 `rust_engine`。
这些是引擎代码，应保持通用；模型的个性化一律放在该模型的资源与 `liltoon_materials.json` 里
（显式声明原则）。只有当需要**新增一种渲染能力**（如真正的法线贴图、新的 pass）时才改引擎，
且必须同时保证：不破坏已发布形态、不污染其他实体/光影状态、所有绘制状态恢复。

**两处你会偶遇的引擎入口（正常开发不需要改）**：
- `com.shiroha.mmdskin.MmdSkinClient`：初始化渲染客户端（模组入口只调用 `initClient()`）。
- `com.shiroha.mmdskin.render.entity.MmdSkinRenderer`：PMX 渲染器（渲染器模板里 new 它）。

> **引擎内部模块（一般不改，改前须全链可达性核查）**：`ClientRenderRuntime` 是客户端渲染组合根，
> 每次启动都会实例化并配置 `compat.vr`、`compat.iris`、`debug`、`scene`、`expression`、`ui.wheel(.service)`
> 等模块，因此它们是**活跃代码**，不要当作未使用删除。`stage` 包静态可达但**功能从未被初始化**
> （`StageClientBootstrap` 无人调用），属"可达但休眠"。
>
> 已按静态可达性**移除**的孤儿引擎类（`com.moze.openmmdchanged` 不引用，`ClientRenderRuntime` 也不可达，
> 并已重新编译验证）：
> - 模型选择/操作轮盘 UI：`ui.selector/**`、`ui/QuickModelSwitcher`、`ui/network/NetworkOpCode`、
>   `ui/wheel` 的 `ActionWheelScreen`/`ConfigWheelScreen`/`MaidConfigWheelScreen`、
>   `ui/wheel/service` 的 `ActionOption`/`ActionWheelService`/`DefaultActionWheelService`、
>   `ui/config` 的 `ActionWheelConfig`/`ActionWheelConfigScreen`。
> - maid 非核心：`compat/maid/{network,render,service,ui}`（保留 `maid.model`/`maid.runtime`）。
> - stage 休眠部分：`stage/server/**`、`stage/client/bootstrap/StageClientBootstrap`、`stage/domain/model/StagePlaybackPlan`。
> - 其它：`compat/vr/VRHandRenderer`。
>
> VR 并未整体删除：`DefaultVrRuntimePort`、`VRBoneDriver`、`VRDataProvider`、
> `VivecraftTrackingDataReader`、`VivecraftVrTrackingFacade`、`VRArmHider` 及原生 VR IK 接口仍保留，
> 负责头显/左右手追踪、手臂骨骼驱动和第一人称手臂隐藏。删除的 `VRHandRenderer` 只是一个没有调用入口、
> 会与 Minecraft/Vivecraft 手持物渲染重复的静态物品绘制器。
>
> 若再删引擎代码，需重新跑一遍"种子→可达性"分析并 `compileJava` 验证，不能只靠静态结论。
> 同理，`rust_engine/Cargo.toml` 里的 `viewer` 与 `vr_demo` 特性（及对应 demo bin）属开发演示用途，
> 模组正式构建（`cargo build --release`，默认特性）不编译它们。
> 材质级的旧式"青色即发光"路径（`cyanEmissionStrength`/`lilCyanEmissionStrength`）已移除；
> `emissionLayers` 里 `maskMode:"cyan"`/`"color"` 的逐层颜色筛选仍保留，仅供无蒙版贴图时按层降级使用，
> 新资产一律用 `maskMode:"texture"` 的独立蒙版（见 `docs/命名与资产规范.md` §8）。

## 5. 常见坑

- **改了文件没生效**：`asset.list` 没写该文件，或文件名大小写不一致。
- **贴图紫黑**：PMX 内相对路径与磁盘路径/大小写不一致，或没进 `asset.list`。
- **暗处全身发光**：把 Base Color 当发光图，或给不该发光的材质开了 `useEmission`。
- **基础色变浅**：把发光烘焙回了 Base Color。
- **角不跟头**：角的顶点权重没绑到 `Head` 或其子骨。
- **腿不动**：VMD 腿骨/IK 名与 PMX 不一致，或权重绑错骨。
- **改引擎后光影包异常**：新增 pass 必须恢复着色器/状态，参考 `mixin/client/LevelRendererMixin.java`。
