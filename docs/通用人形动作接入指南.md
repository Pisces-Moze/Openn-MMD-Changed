# 通用人形动作接入指南（VRChat / Mixamo 通用动作）

> 目标：解决模型默认 A-pose 僵硬。用「任何模型都能套用」的**通用人形动作**替换/补充当前
> 骨骼较少的待机动画。本文是落地说明 + 引擎能力边界 + 许可提醒。

---

## 1. 为什么当前看起来僵硬

- 模型自带的 `anims/idle.vmd`（以及引擎 `default_anim/idle.vmd`）**只动画**了上半身、手臂、
  手指、头颈（36 个骨骼），**没有**动画 `センター`/`下半身`/`腿`/`手腕`。
- 结果：待机时下半身、手腕留在绑定姿态，加上手臂被关键帧定在偏外张角度 → 半摆拍的僵硬 A-pose。

## 2. 为什么「VRChat 自带那套通用动作」不能直接拿来用

- VRChat 的通用动作是 **Unity 人形（Humanoid）** 动画（Hips/Spine/UpperArm…），属 VRChat SDK
  内容，**不能再分发**，而且**不是 MMD 骨骼**格式。
- 但引擎已经支持「通用人形动作 → MMD 骨」的映射，这正是它的通用性来源。

## 3. 引擎已具备的通用人形能力（确认可用）

- `rust_engine/src/animation/fbx_bone_mapping.rs`：把 **Mixamo** 与 **Unreal Mannequin** 的人形骨骼名
  映射到 MMD 标准骨（`Hips→センター`、`LeftArm→左腕`、`LeftUpLeg→左足`、`LeftHand→左手首`…）。
- `rust_engine/src/animation/fbx_loader.rs`：完整 FBX 解析器，处理坐标系（含 Blender Z-up）、
  动画曲线、AnimationStack，并内置**手臂/肩膀动态重定向**
  (`FBX_RETARGET_REV = "fbx-retarget-2026-03-02-arm-shoulder-dynamic"`)，专治 A-pose 僵硬。
- `AnimationLibrary`：按槽位名（`idle`/`walk`/`sprint`…）加载 `.vmd` 或 `.fbx`；FBX 每文件一个动画时
  直接加载首个 Stack；还支持 `#动画名` 形式选择多动画 FBX 的某个 clip。

> 结论：**引擎侧已就绪**，无需改引擎。需要的是把 Mixamo FBX 动作**正确放进模型目录**。

## 4. 接入步骤（你提供 Mixamo 人形 FBX）

### 4.1 在 Mixamo 导出

1. 登录 [Mixamo](https://www.mixamo.com)，上传任意人形（或用 Mixamo 内置角色）。
2. 为每个动作导出 **FBX**（`Format: FBX for Unity` / `FBX`，`Skin: Without Skin`），
   每个动作一个文件：`idle.fbx`、`walk.fbx`、`run.fbx`（对应本模组的 `sprint` 槽）。
3. 导出时确保动画为**循环可用**(Loop)的 idle / walk / run；结尾可回起点。

### 4.2 命名与放置

放到模型的动画目录（JAR 内）：

```text
src/main/resources/assets/openmmdchanged/mmd/<id>/anims/
├── idle.fbx       # Mixamo idle
├── walk.fbx       # Mixamo walk
├── run.fbx        # 对应 sprint 槽；也可命名 sprint.fbx
└── (可保留其它 .vmd，如 die.vmd / sneak.vmd)
```

### 4.3 更新 asset.list

在 `anims/` 对应目录的 `asset.list`（模型目录根的 `asset.list`）中逐行列出新增 FBX：

```text
anims/idle.fbx
anims/walk.fbx
anims/run.fbx
```

漏写的文件不会被安装到运行目录，模型找不到。

### 4.4 处理 VMD 与 FBX 的优先级

`AnimationLibrary` 对同一槽位按 `.vmd` → `.fbx` 顺序尝试。若 `idle.vmd` 与 `idle.fbx` 同时存在，
**会加载 `.vmd`**。所以想用 Mixamo idle，要做其一：

- **方法 A（推荐，简单）**：把要换成 FBX 的 `.vmd` 换成同名 `.fbx`（例如删掉/改名 `idle.vmd`，
  只留 `idle.fbx`）。其它不想换的动作保留 `.vmd`。
- **方法 B（精确控制）**：用 `ModelAnimConfig`（模型目录 `animations.json`）把槽位映射到具体文件：
  ```json
  { "idle": "idle.fbx", "walk": "walk.fbx", "sprint": "run.fbx" }
  ```
  这样不删 `.vmd` 也能指定用 FBX，且可把 `run.fbx` 映射到 `sprint` 槽。

### 4.5 编译 + 进游戏验证

```powershell
.\gradlew.bat compileJava
```
进游戏按 `docs/附属模组开发与模型接入指南.md` §14.2 测试清单验证 `idle/walk/sprint/sneak/die`。

## 5. 许可提醒

- **Mixamo**：Adobe 官方注明**可免费用于个人与商业项目**（通常不需署名），但**不要把导出物以
  "Mixamo/Adobe" 名义再分发**；在模组里注明来源即可（合规上建议保留出处说明）。
- **VRChat 自带动作**：随 SDK，**不可再分发**。
- **社区 MMD 舞蹈/动作**：多标注「仅限个人使用/禁止转载」，**不要**直接打包进模组。
- **生成式/自建动作**：无许可风险，但需进游戏确认绑定与方向正确。

## 6. 骨骼兼容注意（若部分骨骼不动）

Chalo 模型部分骨名可能**非 MMD 标准**（如肩用 `左肩P` 而非 `左肩`）。Mixamo 映射目标是标准名
（`左肩`），若模型实际名称不同，该骨会**不匹配**（保持绑定）。可用两种方式兜底：

- 在模型目录 `liltoon_materials.json`/`animations.json` 相关映射里把槽位对到正确文件；或
- 在 Blender 里把模型的 MMD 骨名规范化为标准名后再导出 PMX（推荐，能同时改善所有动作兼容）。

> 核心骨（`センター`、`上半身`、`腕/ひじ/手首`、`足/ひざ/足首`、`首/頭`）一般都能匹配上，
> 待机/走路/跑步的主干动作即可正确套用。

## 7. 不想用外部资源的替代方案

若不想引入 Mixamo：可让我生成一份**合成自然 idle**（把该模型实际拥有的骨骼都钉到绑定姿态 +
轻微呼吸，全身无遗漏）。它无许可风险、可直接内置，但**手臂是否下垂取决于模型的绑定姿态**，
需你进游戏确认效果。

## 8. 实测结论（Mixamo FBX → 本模型）

**引擎侧修复（已完成并验证）**：
- `fbx_loader.rs`：无 stack 指定时改选**曲线节点最多的 stack**（Mixamo 把动画放非首个 stack，旧逻辑取首个空
  take → 0 骨轨道）。修复后 `Orc Idle.fbx` 可提取 52 骨轨道。
- `fbx_loader.rs` **根高度归一化**：FBX 根骨（センター）带一个相对静止姿态的垂直位移（实测 Y≈-3.9），直接
  应用会让整模型陷入地面。现在把根骨垂直位移清零，模型回到绑定高度、脚贴地。
- `humanoid_role.rs` + `bone_set.rs`：VRChat 式**按角色找骨**（动画骨名与模型骨名不一致时兜底）。
- 修改这些文件后至少执行 `cargo test humanoid_role --lib`、`cargo build --release` 和
  `gradlew compileJava processResources`，并把新 DLL 同步到 `src/main/resources/natives/windows-x64/`。

**仍存在的模型级问题（非引擎可简单解决）**：
- **按下 Shift（潜行）变 T-pose**：`sneak.vmd` 只动画 `上半身/センター`（2 骨），其余骨（手臂等）
  落到**绑定姿态**。而该模型是从 Unity/FBX 转的，**绑定姿态本身就是 T-pose** → 任何没把所有骨都打上
  关键帧的动作都会露出 T-pose 手臂。这是**模型绑定姿态**问题（需在 Blender 重摆绑定为自然站姿，并让
  `sneak.vmd` 等动作的手臂也打上关键帧）。

**当前状态**：已接入 6 个通用人形 FBX 动画，并新增「漂浮」动画状态与触发器：
- `站立.fbx → anims/idle.fbx`（待机）
- `行走.fbx → anims/walk.fbx`（行走）
- `奔跑.fbx → anims/sprint.fbx`（奔跑）
- `潜行动画（移动）.fbx → anims/sneak.fbx`（潜行）
- `游泳.fbx → anims/swim.fbx`（游泳）
- `水中漂浮.fbx → anims/float.fbx`(「漂浮」状态，见下)
- `animations.json` 显式映射 `idle/walk/sprint/sneak/swim/float`，因此模型专属 FBX 会优先于同名默认 VMD。
- 引擎已**固定根骨**（把 FBX 根骨 `センター` 的三轴位移清零）：模型不再随动画整体下沉/前移/侧移，只保留动作。
  （玩家/实体「**在水面附近、在水里且未接地**」时触发 `float` 状态；`swim` 仅在「游泳且在移动」时触发。
  长按空格在水面踩水会稳定进入 `float`，不再在站立/漂浮间闪烁。见 `AnimationStateManager.resolveLayer0State`、
  `EntityAnimationResolver.resolve`。如需"一进水就漂浮"可把 `!onGround()` 去掉。）
- 潜行动画是持续动作：**潜行且移动 → 播放（循环）**；**潜行未移动 → 暂停保持**（冻结当前帧）。
  （`AnimationStateManager.updateLayer2Animation` 用 `PauseLayer/ResumeLayer` 控制 layer 2。）
- 漂浮仅在实体靠近水面且未接地时触发；深水游泳不会误用漂浮动作。渲染使用稳定水面锚点抵消原版长按跳跃造成的上下浮动，相机高度也会稳定。
- 本模组形态的玩家在水面按住跳跃时，会立即由客户端和服务端共同锁定实际脚部高度并清零竖直速度；
  跳跃按键状态通过独立的小型网络消息同步，不依赖服务端是否及时更新原版 `jumping` 字段。
  因而不会再被原版浮力反复顶起、落下。松开跳跃键、离开水面、开始飞行或检测到约一格内存在可上岸碰撞面时会立即解除锁定。
- 模型稳定偏移和第一人称相机稳定只服从实际锁定状态；松开跳跃键后，两者会立即重新跟随玩家碰撞箱下沉。
- `float` 属于持续动作：进入和保持漂浮状态时会显式启用 layer 0 循环；即使该层此前以非循环方式到达末帧，也会被恢复并继续循环。
- 可用 `model.properties` 的 `floatingPitch`、`floatingTrans` 和 `floatingDepth` 调整姿态。`floatingDepth` 表示模型脚部位于水面以下的格数，默认 `1.25`；数值越小，模型露出水面的部分越多。
- 潜行移动会持续播放动作；停止移动时暂停在当前帧，再次移动时从该帧继续，不会回到第 0 帧。
